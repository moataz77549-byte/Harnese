# Harnese Nova Next — حالة التنفيذ والتحقق

معرّف التطبيق: `com.moataz.harnese.nova`. الإصدار المستهدف `1.3.2`، رقم البناء `15`، ARM64، الحد الأدنى الحالي Android 9.

## ما تغير في الكود

- متحكم تشغيل واحد يملكه التطبيق، وواجهة ViewModel تمرر إليه الاستدعاءات؛ خدمة تيليجرام تستطيع تهيئته دون شاشة الدردشة.
- سجل SQLite للأحداث، وربط المشروع والدردشة والمهمة والمصدر والتوقيت، وطابور إرسال دائم؛ ردود Claude وDeepSeek وAntigravity وأحداث Gradle ونتائج البناء تبدأ من المسارات الحقيقية.
- مزامنة محتوى الإجابات اختيارية من الهاتف؛ الوضع الأولي إشعارات حالة فقط. تجميع الرد مؤقتًا مشفر بمفتاح Android Keystore، وتنقيح أنماط الأسرار المعروفة قبل الإرسال. التنقيح النصي لا يستطيع اكتشاف كل سر غير موسوم؛ راجع المحتوى الذي تسمح بمزامنته.
- تقسيم الرسائل، تقييد معدل الإرسال، إعادة محاولة الرفض المؤكد بحد ثماني محاولات، والاحتفاظ لمدة سبعة أيام. الإرسال ذو النتيجة المجهولة بعد انقطاع الاتصال **لا يعاد تلقائيًا** تجنبًا لتكرار رسالة ربما وصلت؛ يظهر عداده في Agent Hub.
- توسيع أوامر المتابعة والبيئات والبناء والاشتراكات، وأزرار اختيار المشاريع والدردشات، والتحقق من هوية كل Callback. `/apk send` يرسل APK صالحًا من مخرجات المشروع المعتمدة عندما يسمح الحجم؛ لا يرسل مسارًا اعتباطيًا.
- نسخ عمل معزولة لتعديلات الوكلاء، ومراجعة قبل التطبيق على المشروع. فحص بصمات الأصل والمقترح، انتهاء صلاحية، منع إعادة الاعتماد، مصادقة بقفل الهاتف، نسخ احتياطية وتراجع. تحفظ بيانات المراجعة قبل بدء التطبيق لاستعادة حالة الانقطاع.
- مدير MCP لاتصالات HTTPS المتوافقة مع بروتوكولات Streamable HTTP حتى 2025-11-25: اكتشاف الأدوات من الخادم، تمكين لكل مشروع ووكيل، أسرار مشفرة، ومراجعة جميع استدعاءات الأدوات محليًا قبل تنفيذها، مع سجل تدقيق. بروتوكول 2026 وOAuth التفاعلي وتوصيل أدوات MCP تلقائيًا إلى CLI الوكلاء ليست مكتملة في هذا الإصدار.
- إصدار Offline يتطلب وجود حزم Core وPython وAndroid وTypeScript وClaude وDeepSeek أثناء البناء؛ يفشل البناء عند غيابها. لا يتضمن Antigravity أو PHP أو C/C++ كحزم إضافية. تنزيلها اختياري من الهاتف.
- قياس الحزم بعد التحقق من SHA-256، ومترجم TypeScript حقيقي، وفحص مساحة قبل النسخ والاستخراج. تستخدم الحزم بيئة Linux مشتركة واستخراجًا تدفقيًا.
- صفحة بيئات البرمجة وفحوص فعلية يمكن طلبها من الهاتف أو تيليجرام؛ `/runtimehealth` يحاول إنشاء مشروع Kotlin وبناء APK باستخدام Gradle Offline، ويسجل رمز الخروج الفعلي.
- نشر الإصدار محمي بشهادة المالك الأصلية؛ لا يُنشأ مفتاح عشوائي. مسار النشر يرفض غياب المفتاح أو اختلاف البصمة أو فشل اختبار Offline.

## حدود ينبغي معرفتها قبل الإصدار النهائي

- PRoot ليس عزلًا أمنيًا لنظام التشغيل. مساحة مراجعة المشروع تحمي تطبيق تغييرات الملفات المعتادة، ولا تجعل أوامر shell أو أدوات خارجية غير موثوقة آمنة تلقائيًا.
- النسخ المعزولة تحد حاليًا المشروع بعشرة آلاف ملف و200 MiB من الملفات القابلة للنسخ. تحفظ Git وتبعيات المشروع العادية والروابط الداخلية؛ لا تنسخ مخرجات `build` وذاكرة Gradle المؤقتة. تُرفض الروابط الخارجة عن المشروع.
- استكمال استجابة الوكيل بعد قتل عملية Android ليس مضمونًا. عمر المهام منفصل عن الشاشة، لكن الإيقاف القسري وقيود Android يوقفان الخدمة. الرسائل المؤكدة المخزنة تبقى للإرسال اللاحق.
- تعديل رسالة تيليجرام أثناء توليد الإجابة لم يكتمل؛ النتائج النهائية وإشعارات الحالة هي المسار المتاح.
- الأدوات الحالية ونسخ النماذج على هاتف المستخدم وحساباته تتطلب فحصًا على ذلك الهاتف؛ لا يستدل على توفر نموذج من اسمه وحده.

## دليل التحقق

نجحت اختبارات وحدات وبناء Debug وRelease للدفعات الأولى على GitHub Actions، ومنها اختبارات عزل التعديلات والبصمات والتراجع وحماية النصوص. يجب الرجوع إلى تشغيل CI الخاص بآخر Commit قبل اعتماد آخر دفعة.

مسار `nova-offline-verify.yml` يحمّل الحزم المطابقة للبصمات، ويولد نموذج Kotlin من مولد التطبيق نفسه، ثم يحاول تشغيل Python وTypeScript وGradle في ARM64 مع تعطيل الشبكة. لا تُعتبر تسمية حزمة أو وجود برنامج تنفيذي نجاحًا. فشل أي خطوة يمنع اعتماد الإصدار النهائي.

الاختبار على Linux ARM64 لا يعوض اختبار Android/PRoot: ملف AAPT2 الموجود في الحزمة يستخدم `/system/bin/linker64`. يجب إثبات عمله مع مكتبات Android الحقيقية. لا يُعلن نجاح بناء APK دون إنترنت إلا عند وجود APK ناتج وسجل اختبار ناجح.

حزمة المالك المتوفرة تطابق شهادة Nova 1.3.1 العاملة. بصمة SHA-256 العامة للشهادة:
`d7f31fde154fc9b46fe8ef333fd12ecdfbd9b331d71a5284c24a6ad8ad45de51`.
لم توضع مفاتيح التوقيع أو كلمات المرور في المستودع.

## متطلبات النشر الآمن

يلزم توفير أسرار GitHub Actions: `NOVA_KEYSTORE_BASE64`, `NOVA_STORE_PASSWORD`, `NOVA_KEY_PASSWORD`, `NOVA_KEY_ALIAS` من مفتاح المالك الأصلي، ثم تشغيل نشر من نفس Commit الذي اجتاز اختبار Offline. يلزم أيضًا اختبار قفل الشاشة، استمرار إشعارات تيليجرام في الخلفية، وأوامر الوكلاء والبناء على جهاز Android فعلي. يحتفظ النشر بملف APK مباشر وSHA-256 وبيان تحديث، ويرفض استبدال إصدار منشور سابقًا.
