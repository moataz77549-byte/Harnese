# تحديث Harnese دون التضحية ببيانات النسخة السابقة

**هام:** بناء GitHub Actions السابق [41259582715](https://github.com/moataz77549-byte/Harnese/actions/runs/41259582715) موقّع بشهادة Debug مختلفة عن 1.2.0. المستودع لا يتضمن مفتاحه الخاص. لا يمكن توقيع تحديث متوافق بمجرد استخراج APK القديم. لا تحذف التطبيق القديم قبل أخذ نسخة احتياطية مؤكدة.

## طريقة آمنة لتجربة الواجهة الجديدة دون حذف القديم
بدءًا من 1.2.1، ننشر artifact إضافيًا باسم \`harnese-parallel-debug-arm64\` مع Package ID هو \`com.jarves.harnese.parallel\`. يُثبت بجانب القديم، ولا ينقل البيانات تلقائيًا؛ وهو خيار معاينة مستقل. البنية الأساسية ما زالت \`com.jarves.harnese\`.

## نقل المشاريع والدردشات من النسخة القديمة إلى العادية الجديدة (يتطلب حاسوبًا)
هذا المسار يدعم نسخ Android **Debug** التي تسمح لـ \`adb run-as com.jarves.harnese\` بالوصول إلى ملفات التطبيق. لا يحتاج روت، لكنه **يتطلب USB debugging وحاسوبًا مع Python 3 وAndroid platform-tools (adb)**. بعض هواتف الشركات قد تمنع \`run-as\` حتى مع نسخ Debug؛ في هذه الحالة لن نلمس التطبيق القديم.

1. ثبّت Android Platform Tools على الكمبيوتر، فعّل USB debugging، وصل جهازك. احفظ أي عمل غير مكتمل داخل Harnese ثم أغلقه.
2. نزّل سكربت \`scripts/migrate-harnese-debug.py\` من هذا المستودع ونفّذ:
   \`\`\`bash
   python3 scripts/migrate-harnese-debug.py backup --directory ~/harnese-safe-copy
   python3 scripts/migrate-harnese-debug.py verify --directory ~/harnese-safe-copy
   \`\`\`
3. سترى داخل \`~/harnese-safe-copy\` نسخة للمشاريع والدردشات وملف **APK المثبّت نفسه** للتراجع، إضافة إلى بصمات SHA-256. احفظ المجلد محليًا ولا تشاركه لأنه يحتوي على ملفاتك ومحادثاتك.
4. نزّل **APK العادي** من artifact \`harnese-online-debug-arm64\` (وليس parallel)، ثم:
   \`\`\`bash
   python3 scripts/migrate-harnese-debug.py upgrade --directory ~/harnese-safe-copy --apk /path/to/app-online-debug.apk
   \`\`\`
5. السكربت يتحقق من النسخة الاحتياطية ومن شهادة كل APK. عند اختلاف التوقيع يطلب كتابة \`MIGRATE\` قبل حذف التطبيق القديم. يثبت الجديد ويعيد ملفات المشاريع والدردشات، ويعيد تهيئة حالات التسجيل/بيئة Linux التي لا تصلح بعد حذف التطبيق. يحاول استرجاع النسخة السابقة تلقائيًا إذا فشلت الترقية، لكنه لا يستطيع ضمان نجاح التراجع في كل حالات فشل الجهاز أو نقص التخزين.

### ما يُحفظ وما لا يُحفظ
- يُنقل: \`files/workspaces\` (مصادر المشاريع)، \`files/chats\` (سجل المحادثات)، \`shared_prefs/pocket_preferences.xml\` (فهارس المشاريع والإعدادات)، وبعض ملفات السجل المحلي.
- لا يُنقل: قاعدة Linux الضخمة داخل \`files/runtime\`، أو \`pocket_secrets.xml\` أو \`harnese_telegram_private.xml\`، أو مفاتيح Android Keystore. **يلزم إعادة تنزيل بيئة التشغيل وتسجيل الدخول إلى الخدمات وإدخال مفاتيح API من جديد.**
- السكربت يتجاهل الروابط الرمزية والملفات غير العادية لتجنب استعادة مسارات خارج بيئة المشروع. بعض التبعيات المولَّدة بواسطة symlinks قد تتطلب إعادة تثبيت.
- إذا كنت تستخدم نسخة Release غير قابلة لـ \`run-as\`، أو لا تمتلك حاسوبًا، فلا تستخدم هذا المسار. احتفظ بالقديم واستخدم نسخة Parallel للتجربة.
- خاصية \`android:allowBackup="false"\` تعني أن نسخ Android Backup الافتراضية ليست بديلًا مضمونًا.

### ملاحظات حول التوقيع مستقبلًا
- يجب إنشاء ملف keystore خاص بمالك التطبيق وحفظه في مكان آمن خارج GitHub. ثم استعماله **في كل إصدار** عبر إعدادات توقيع Release في Gradle وGitHub Actions Secrets.
- لا تحفظ كلمة مرور أو مفتاح توقيع خاصًا في المستودع أو في محادثات عامة.
- إنشاء مفتاح ثابت جديد لا يجعله متوافقًا مع شهادة Debug القديمة، لكنه يمنع تكرار المشكلة في الإصدارات القادمة.
